# KabadiLink — Database Schema (01 of 9)

Target: Postgres (Supabase as primary with Storage; Neon as database-only fallback). Existing tables from the base repo are marked **(existing,
extend)**; everything else is **(new)**. Use `uuid` primary keys for anything referenced across
channels (lots, offers, users); `serial`/`bigserial` is fine for internal-only tables
(audit_log, notifications).

Apply via a migration tool of your choice (Alembic is the natural fit for FastAPI) — don't
hand-run ad-hoc SQL against production.
